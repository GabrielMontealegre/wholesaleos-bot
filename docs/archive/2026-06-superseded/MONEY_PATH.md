# Money Path

## Canonical Flow

WholesaleOS must move every deal through one money path:

```text
Opportunity
-> Identity
-> Evidence
-> Contact
-> Comps
-> ARV
-> Repairs
-> MAO
-> Offer
-> Call Script
-> Buyer Match
-> Title
-> Closing
-> Profit
```

## Meaning Of Each Step

- Opportunity: a possible deal worth investigating.
- Identity: canonical property identity and complete address.
- Evidence: source-backed facts proving status, motivation, and relevance.
- Contact: phone, email, form, reply route, owner route, or paid lookup need.
- Comps: verified sold comparable properties with source URLs.
- ARV: unlocked only from enough verified comp evidence.
- Repairs: unlocked only from visible repair evidence or explicit manual input.
- MAO: unlocked only from ARV plus repair assumptions or evidence.
- Offer: unlocked only when enough numbers and strategy are supported.
- Call Script: generated only when identity and contact/outreach route exist.
- Buyer Match: connects deal profile to real buyer demand.
- Title: identifies title workflow, risks, and closing requirements.
- Closing: tracks transaction execution.
- Profit: assignment fee or realized wholesale outcome.

## Lock Principle

Missing evidence is not a failure. Hidden missing evidence is a failure.

Every locked state must produce a work order:

- missing source proof -> verify property source
- missing contact -> find contact route
- missing comps -> run comp research
- missing repairs -> capture repair evidence
- missing ARV -> calculate ARV after comps
- missing MAO -> calculate MAO after ARV and repair evidence
- missing offer -> draft offer after MAO or approved exploratory strategy

## Operator Output

Each Opportunity should tell Gabriel:

- current stage
- progress percentage
- next best action
- what is ready
- what is missing
- why numbers are locked
- what he can do now
- what the system can do next
- what requires paid data
