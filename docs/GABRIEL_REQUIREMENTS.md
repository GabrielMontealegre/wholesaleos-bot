# Gabriel Requirements

## First User

Gabriel is the first user. Build for his acquisition workflow before building
for a generalized SaaS audience.

## What Gabriel Needs

Gabriel wants numbers on every deal, but numbers must be honest.

Every Opportunity must show:

- property identity
- source evidence
- motivation evidence
- contact route
- comp status
- ARV status
- repair status
- MAO status
- offer status
- next best action
- missing evidence
- risks
- work orders

## Locks Must Be Useful

Every lock must explain what is missing and what to do next.

- ARV locked -> need verified sold comps
- MAO locked -> need ARV and repair evidence or manual repair input
- offer locked -> need MAO or approved exploratory strategy
- call locked -> need contact route
- contact lookup required -> skip trace or public route required

## Buyer And Title Matter

WholesaleOS is not complete at offer generation. Gabriel also needs:

- buyer list context
- likely buyer demand
- title company workflow
- closing readiness
- assignment execution support

## Dashboard Standard

The dashboard must be understandable to Gabriel. It should show one clean
Opportunity card with:

- headline
- badge
- stage
- progress
- next action
- missing evidence
- lock states
- risks
- suggested buttons

Do not bury the money path in debug JSON.

## Product Direction

Do not build abstract SaaS first. Build the operator system that helps Gabriel
decide who to call, what to say, what number to discuss, what proof is missing,
and what work the system should perform next.
