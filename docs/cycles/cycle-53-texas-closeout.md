# Cycle 53, PR 1: Texas close-out and reusable card explanations

The public comp lane stays off in non-disclosure states, including Texas. Operator-confirmed sold-property screenshots remain available. A verified public sales profile opens the existing public comp engine in its market; a market without one remains pending. This does not create a new source or change a comp threshold.

Every preview row now has a read-only priority, deal-fit explanation, one next step, and plain-English glossary. Holding-period claims require a sourced prior recorded sale. A deed date alone is not a recorded sale. A foreclosure notice does not establish the current balance or equity. A county assessment is neither ARV nor debt. A property without a verified distress signal can rise no higher than WORTH_A_LOOK. Quarantined rows remain blocked from contact regardless of the displayed research priority.

The prior equity projection subtracted an original mortgage amount as though it were a current payoff. It now keeps the original amount as a sourced clue but reports estimated debt, equity, and room to offer as unknown until a current total payoff is established. Read-time projection also overwrites old persisted equity and room-to-offer values. The original amount is labeled "Original loan amount - not the current payoff." wherever it renders. This can reduce the number of rows shown as having room to offer; it is an honesty correction, not a loss of source evidence.

Paid comps remain off. The frozen `PAID_COMP_ADAPTERS` registry is empty, so environment settings alone cannot enable them. No provider is selected and no key is configured in this release. Future activation requires a registered adapter, all three state-scoped environment settings (`WOS_PAID_COMP_ENABLE_<STATE>=true`, `WOS_PAID_COMP_PROVIDER_<STATE>`, `WOS_PAID_COMP_KEY_<STATE>`), and a trusted caller-supplied subject row whose state matches the comp's location state. The candidate's own `subject_state` is ignored. Existing callers pass no subject and therefore reject paid comps. The key value is never returned, logged, or placed in a payload. A candidate must identify the registered provider, use `recorded_sale` or `mls_closed_sale` as its price basis, have ordinary provenance, and pass the unchanged strict comp grid. Estimates and AVMs cannot count. No connector runs from this change.

A future paid-adapter cycle must issue a trust marker that untrusted AI analyzer output, screenshot capture, manual/packet imports, and request bodies cannot carry. It must strip or reject inbound `source_kind: paid_api` unless the record came from the registered adapter. This is not implemented here.

The existing source-date normalization accepts a spelled-out date such as `October 6, 2026`. Slash and numeric-dash dates remain `ambiguous_numeric_order` and quarantined. P7's bare numeric-date acceptance is waived: accepting it in the lifecycle parser would bypass the Cycle 50 safety rule. A stored `sale_date_iso` never overrides a conflicting raw event date.

DEFERRED, not implemented: resolve numeric dates only with proof of date order. Allowed rules are (1) only one interpretation is a valid calendar date because a component exceeds 12; (2) a named-month date in the same document matches exactly one interpretation; or (3) a Texas Chapter 51 trustee-sale notice from a registered source adapter has exactly one interpretation that is a legal sale day under Tex. Prop. Code 51.002(a): the first Tuesday, or first Wednesday when the first Tuesday is January 1 or July 4. Store `sale_date_resolution` with `raw_text`, `raw_field`, `resolved_iso`, `rule_id`, `source_url`, `source_adapter_id`, and `evidence_excerpt`. The lifecycle must re-derive the result from raw inputs, not trust stored ISO or rule ID. This design needs a separate reviewed change.

ArcGIS parcel profiles may now allowlist either MapServer or FeatureServer paths, including an ArcGIS Online organization prefix. Optional living area and beds/baths use the existing county apply path. A parcel's prior sale is recorded separately as `last_recorded_sale_date` and `last_recorded_sale_price`, never as a foreclosure event date; ambiguous raw dates are retained for review without an ISO date. The Ellis profile and its existing record shape remain unchanged.
